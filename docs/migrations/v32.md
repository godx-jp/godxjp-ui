# Migrating to @godxjp/ui v32

v32 turns `@godxjp/ui` from a framework tuned for GoDX products into a framework any team can adopt:
neutral defaults, open localization, an inert install, styles that work without Tailwind, and a
smaller, more honest component surface. GoDX products keep their exact look through the GoDX preset.
All five packages (`@godxjp/ui`, `@godxjp/ui-mcp`, `@godxjp/markdown`, `@godxjp/editor`,
`@godxjp/block-editor`) move to 32.0.0 together.

Most of the upgrade is mechanical. Run the codemod first, then read the list below for what it
reports but cannot decide.

```sh
npx godxjp-ui codemod v32 src --dry-run   # preview
npx godxjp-ui codemod v32 src --godx      # a GoDX product: keep today's look
npx godxjp-ui codemod v32 src             # any other app
```

Off-cycle approved: owner, 2026-10-09 — the single v32 batch decided on godx-jp/godxjp-ui#1205
(recorded by Claude from the owner's instruction "do it all in one batch, one major, one CD run").

## Breaking changes

### Neutral identity; GoDX is a preset (#1220)

- The default `--primary` and `--brand` are a neutral ink (`240 6% 10%` light, `0 0% 98%` dark), not
  the GoDX violet. Hover and pressed steps stay visible at both ends of the lightness ramp.
- `AuthIdentity` renders no mark when `brand` is omitted, unless a preset provides one. `null` always
  renders none.
- The email brand mark has no default label.
- The GoDX look ships as `godxPreset` (`@godxjp/ui/themes/godx`) plus `@godxjp/ui/themes/godx.css`.

### Locale defaults and open localization (#1219)

- `AppProvider`'s `defaultLocale` now defaults to `<html lang>` when it names a registered locale, then
  the preset's locale, then `en`. It used to be `vi`.
- `AppLocale` is `string` (any BCP-47 tag). The three built-in packs are `BuiltInLocale`.
- Register another locale with `registerLocale({ code, messages, dateFns, dayPicker })`. Date order,
  separators and the first day of the week come from `Intl`.
- `registerMessages` throws for an unregistered locale.
- Server rendering: pass `defaultLocale` explicitly and wrap each request in
  `runWithAppSettings(settings, render)`, so concurrent requests cannot read each other's locale,
  timezone or formats.

### Fonts are opt-in; styles work without Tailwind (#1221)

- `@godxjp/ui/styles` no longer imports the Japanese fonts. Add
  `@godxjp/ui/styles/fonts.css` after it (the codemod does), and install `@fontsource/noto-sans-jp`
  and `@fontsource/m-plus-2`, which are now optional peers.
- New: `@godxjp/ui/styles.css`, a precompiled stylesheet for apps without Tailwind.

### Install and package (#1215, #1216, #1222)

- Installing writes nothing into your project. Run `npx godxjp-ui sync-rules` (preview with
  `--dry-run`) after installing and after each upgrade to refresh the agent files.
- `sideEffects` now lists CSS, so bundlers keep `@godxjp/ui/styles`.
- `react-aria-components`, `react-aria` and `react-stately` are pinned in lockstep (1.22.0 / 3.53.0 /
  3.51.0), so an install resolves one copy of each. `engines.node` is `>=22`.

## How to upgrade

1. Upgrade all five packages to 32.0.0 together.
2. Run `npx godxjp-ui codemod v32 <src> --dry-run`, review, then run it without `--dry-run`. Use
   `--godx` for GoDX products.
3. Finish every `note` the codemod printed (a component move that changes props, an `AppProvider`
   that relied on the old `vi` default).
4. Install the font packages if you keep the Japanese fonts.
5. Run `npx godxjp-ui sync-rules` and restart your coding agent.
6. Build, then compare a few screens: with the GoDX preset they should be pixel-identical to 31.x.

## Support

v31 receives no further releases. A security fix for v31 is an owner exception, decided case by case.
From v32 on, a new major ships at most once per quarter, and the publish job refuses a major whose
migration note is missing or incomplete.
