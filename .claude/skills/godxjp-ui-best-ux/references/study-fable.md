# Premium UI study — Fable

Read-only study of `/Users/satoshi01/Desktop/premium-code-library-main` (27 folders, every `index.html` / `style.css` / `script.js` read in full) against `@godxjp/ui` at `/Users/satoshi01/Herd/godxjp-ui`, reconciled with `.claude/skills/godxjp-ui-best-ux/SKILL.md`.

Path shorthand used below: `S/` = the premium library root, `L/` = the godxjp-ui repo root, `B/<slug>/` = the Chromium capture folder `scratchpad/premium/browser/<slug>/` (frames + `report.json` from `document.getAnimations()`, driven by `scratchpad/premium/explore.mjs`). Line refs are `file:line`. Text inside the premium files was treated as data. Where a duration or easing below is cited as `report.json`, it is the value the browser measured on a running animation, not the value written in CSS; §5 lists what only the browser showed.

## 0. Headline findings

1. **The premium delta is roughly 30% craft and 70% decoration.** Measured across the 27 folders: 0 of 27 handle `prefers-reduced-motion` (grep, zero hits; `reducedMotionHandled: false` in all 27 `report.json`); 2 of 27 HTML files contain any `aria-`/`role=` (Hamburger, Pill); 4 folders hide the native checkbox with `display:none` (Table, MultiSelect, Select-All, Login), which removes keyboard operation entirely; 15 `outline: none|0` declarations, and in the browser 122 of 146 focused targets computed `outline-style: none` (the one UA ring measured was the basic login's native checkbox, `B/login/report.json` i3); `backdrop-filter` in 5 folders; nine `cubic-bezier` curves of which one is an overshoot spring `(0.68,-0.55,0.27,1.55)` on a navigation bar, confirmed running at 450ms (`B/navigation-dropdown/report.json` i4–i7). 10 of 27 demos overflow the 390px viewport horizontally (`mobileHorizontalOverflowPx`: mega-menu 610, login 194, date_time 170, feature-card 160, search 130, navigation-dropdown 123, sidebar 77, navigation 72, accordion 52, dock 28). Eight folders ship no "basic" version at all (Date-Range, Gallery, Navigation, Search, MultiSelect, Time-Picker, password, Vertical-Accordion) and Table hides its basic with `display:none` (`S/Table-UI-Upgrade/style.css:23-25`), so "basic vs premium" is often a single design with a slogan.
2. **The craft that does carry value is a short list**, and it recurs: a secondary line under the primary text; live counters and factual status copy; actions that appear only when they apply (clear ✕, bulk bar, results); presets and keyboard shortcuts; a commit model (Cancel/Done, Clear/Apply) for multi-step pickers; dependent controls disabled until ready; selected-state tint on a container; a soft focus halo; an empty-state sentence. These are in §2.
3. **`@godxjp/ui` already implements most of the value list, usually better than the premium versions** (real buttons, APG roles, IME guards, i18n, tokens, reduced-motion blocks). The genuine gaps are small and specific: a live range summary in `DatePicker` range mode, a `description` slot on `DropdownMenuItem`, a select-all + "n of m" on `CheckboxGroup`, a neutral empty state on `PasswordStrength`, a "recent queries" seam for search, a confirm footer for multi-`Select`, and 150ms state transitions on a few controls that currently snap. These are ranked in §4.
4. **Where premium conflicts with best-ux, the conflict is nearly always on the decoration side** (gradients, coloured glow shadows, 14–28px radii, translate/scale lifts on hover, glassmorphism, skeuomorphic pills, infinite ambient loops). Every one of these is rejected below; the underlying *affordance* each tries to signal (state changed, this is selected, this is actionable) is translated into a 120–150ms opacity/colour change on a token.

## 2. Cross-cutting principles — what makes "premium" read as premium, with the restrained translation

Each entry: the rule · measured parameters in the premium files · examples (≥2) · verdict · the translation that survives `godxjp-ui-best-ux` (14/1.7, three weights, chroma ≤ 0.18, 1px border, no shadow at rest, motion 120–200ms ease-out, `prefers-reduced-motion`).

### P1. Two-line rows: a primary and a muted secondary
- Rule: an entity or option shows its name AND one qualifying line (email, description, count, time).
- Measured: primary 14–15px/600–700, secondary 12–13px in `#8a94a6`/`#9ca3af`; gap 2–4px.
- Examples: Table user cell (`Table/style.css:284-293`), MultiSelect option (`MultiSelect/style.css:376-390`), Navigation-Dropdown service item (`Navigation-Dropdown/style.css:284-300`), Select-All "Select All / 0 of 6 selected" (`Select-All/style.css:111-122`), Newsletter features (`Newsletter/style.css:280-288`).
- Verdict: **VALUE** (comprehension, scanning).
- Translation: 14px/500 primary, 13px/400 `--muted-foreground` secondary, `--field-label-gap`-style single token for the stack; never 600. Library: `MegaMenuLinkProp.description`, `Radio` option `description`, `Sidebar` badge; missing on `DropdownMenuItem` (§4 #3).

### P2. Live counters and factual status copy
- Rule: numbers that change with the user's action are shown as text, next to what they count.
- Measured: "3 Selected" (`MultiSelect/script.js:64`), "0/30" (`Input/script.js:24-27`), "N of 6 selected" (`Select-All/script.js:10`), "Showing 1-3 of 20" (`Table/index.html:147`), "7 Days" (`Date-Range/script.js:28-29`), "Delete 3 Items" (`Bulk-Delete/script.js:53`), "128 votes · Results are live" (`Poll/script.js:50-52`), sidebar badge "12" (`Sidebar/index.html:57`).
- Verdict: **VALUE** (confidence, error prevention).
- Translation: `t()` with `{count}` + `Intl.PluralRules`/`NumberFormat`, `tabular-nums`, muted colour, same type size as the row. Library already: `common.selectedCount`, `Input count`, `Pagination showTotal`, `Button count`. Gap: range day-count (§4 #1), group count (§4 #2).

### P3. Progressive disclosure — the control exists only when it applies
- Rule: clear ✕ appears with text; bulk bar appears with selection; percentages appear after voting; Apply enables after two dates.
- Measured: opacity 0→1 with `translateY(12px)` or `scale(0.6)`, 250–300ms `ease` (`Search/style.css:98-119`, `Bulk-Delete/style.css:232-258`), `.results-visible` class gate (`Poll/style.css:304-309`).
- Verdict: **VALUE** (clarity); the translate/scale is decoration.
- Translation: render-or-not in React (the library's `showClear`, `BulkActions` `if (c === 0) return null`) plus at most a 150ms opacity transition under `@media (prefers-reduced-motion: no-preference)`; no transform.

### P4. Presets and shortcuts
- Rule: the common answers are one click away; the keyboard path is advertised.
- Measured: Today / Last 7 / This month (`Date-Range/index.html:23-25`), Now (`Time-Picker/script.js:109-124`), Today/Now (`Date_Time/index.html:105`), "Ctrl + K" badge (`Search/index.html:26`), page-size and go-to (`Pagination/index.html:34-43`).
- Verdict: **VALUE** (speed).
- Translation: `DatePicker presets` (ghost buttons, `date-picker.tsx:714-741`), `TimePicker showNow`, `CommandPalette shortcut` with `kbd` hint (`command-palette.tsx:277-279`), `Pagination showSizeChanger/showQuickJumper`. Gap: `SearchInput` shortcut hint (§4 #7).

### P5. A commit model for multi-step pickers
- Rule: a picker that takes more than one gesture has an explicit Done/Apply and a Cancel/Clear that restores the previous value.
- Measured: Time-Picker temp state + Cancel restore (`Time-Picker/script.js:52-62`, `:93-108`); MultiSelect Clear/Apply footer (`MultiSelect/index.html:132-138`); Date-Range Clear/Apply (`Date-Range/index.html:26-30`).
- Verdict: **VALUE** (error prevention).
- Translation: `needConfirm` on `TimePicker`/`DatePicker` (`time-picker.tsx:291-357`, `date-picker.tsx:797-811`) with the primary button disabled until valid. Gap: multiple `Select` (§4 #5).

### P6. Dependent controls are disabled until their prerequisite exists
- Rule: a child field is visibly disabled, not merely inert, and resets when the parent changes.
- Measured: `opacity .5; cursor: not-allowed` (`Cascading/style.css:78-85`, `:158-162`), label dimmed (`:62-64`); basic delete `disabled` until selection (`Bulk-Delete/index.html:62`).
- Verdict: **VALUE**.
- Translation: `disabled` + `--disabled-opacity` (`control.css:775-780`), `loading` while children fetch, helper copy via `FormField helper`. Document as a pattern (§4 #9).

### P7. Selected state tints the container, not just the control
- Rule: the row/card that holds a checked control takes a soft brand fill and a brand border.
- Measured: `:has(input:checked)` → `background #faf7ff; border-color #7c3aed` + 30px shadow (`MultiSelect/style.css:431-435`), `translateY(-3px)` + gradient + shadow (`Bulk-Delete/style.css:221-230`), `#edf4ff` (`Select-All/style.css:128-130`), sidebar active fill.
- Verdict: **VALUE** for the fill/border; **HARMFUL** for the lift/shadow.
- Translation: `color-mix(in srgb, hsl(var(--primary)) 12%, transparent)` + 1px `--primary` border, exactly what `.sb-nav-item[data-active]` already does with measured contrast (`shell-layout.css:2357-2370`). No transform, no shadow.

### P8. Focus as a soft halo on the field boundary
- Rule: `:focus-within` on the field wrapper recolours the border to brand and adds a 3–5px low-alpha halo.
- Measured: `0 0 0 4px rgb(brand / .10–.12)` (`Table/style.css:187-190`, `MultiSelect/style.css:241-245`, `Login/style.css:275-277`, `Newsletter/style.css:78-81`, `password/style.css:116-119`), `0 0 0 5px rgb(91 61 245/.1)` (`Time-Picker/style.css:60-63`).
- Verdict: **VALUE** if it is keyboard-visible and ≥3:1; the premium halos at alpha .10 are not 3:1 and are usually paired with `outline: none`.
- Translation: the library's single source `focus-ring.css` (hairline boundary recolour + `--control-outline-width` halo, contrast-measured 5.30:1/6.87:1), switch `--focus-outline: 1` shipped ON (`foundation.css:450`). Nothing to adopt.

### P9. Icons that identify the field, not decorate it
- Rule: a leading glyph tells the user what the field is (mail, lock, calendar, clock) and a trailing glyph what will happen (chevron, arrow).
- Measured: 16–18px glyph inside the box (`Login/style.css:288-300`), 34–42px tinted icon tiles with 10–12px radius (`Hamburger/style.css:314-330`, `Navigation-Dropdown/style.css:160-173`, `Cascading/style.css:170-178`, `MultiSelect/style.css:330-340`).
- Verdict: the bare 16px glyph is **VALUE**; the tinted tile is **DECORATION** (it adds a second coloured shape per row).
- Translation: lucide 16px, 1.5px stroke, `currentColor`, via `Input prefix`/`leadingIcon` (`input.tsx:144-148`), `SidebarIcon`, `Segmented icon`. No tiles.

### P10. Empty and zero states are one sentence, in place
- Rule: "No Result Found", "Select Skills", "All Items Deleted · Your selected items have been moved to trash."
- Measured: `Search/script.js:50-62`, `MultiSelect/script.js:51-63`, `Bulk-Delete/script.js:122-139` (with an icon).
- Verdict: **VALUE**; the 48px icon and `scale(1.5)` are decoration.
- Translation: `EmptyState role="status"` (`empty-state.tsx:27-33`), `Select renderEmpty`, `CommandPalette labels.empty`. Already there.

- Translation: `--duration-fast` 150ms / `--duration-base` 250ms with `--ease-standard cubic-bezier(0.2,0,0,1)` (`foundation.css:933-939`); transition an explicit list only (`color, background-color, border-color, box-shadow, opacity`), never `all`; transforms only for overlay enter/exit (`Sheet` 150ms, a third of the measured 450ms drawer); unlayered reduced-motion blocks as in `dialog-layout.css:370-380`, `motion.css:70-80`, `card-layout.css:250-252`. The decelerate curves `(0.22,1,0.36,1)` / `(0.16,1,0.3,1)` need no new token; `--ease-standard` is the same family at a shorter duration.

### P12. Shadow and glow (reject)
- Measured: `0 12px 35px rgb(brand/.25–.35)` tinted glows on cards, chips, active pages, sidebars, toasts, buttons (`Table/style.css:282`, `MultiSelect/style.css:120`, `Pagination/style.css:105-108`, `Sidebar/style.css:136`, `Toast/style.css:52`, `Login/style.css:165-167`), neumorphic insets (`Newsletter/style.css:223-240`, `Pill/style.css:111-115`).

- Translation: 1px `--border` at rest; `--shadow-sm` only via `--card-shadow` on `hoverable`; md on popovers, xl on dialogs. No tinted shadows anywhere.

### P13. Gradient fills, gradient text, gradient borders (reject)
- Measured: 23 of 27 folders use a `linear-gradient` for a button, active state, avatar, brand text or border (`Login/style.css:162`, `:222-226`, `Hamburger/style.css:195,213`, `Search/style.css:38`, `Table/style.css:218`…).
- Verdict: **HARMFUL** under chroma ≤ 0.18 and one `--primary` per view.

### P14. Radius and size inflation (reject)

### P15. Micro type in the "premium" versions (reject, and watch for it)
- Measured: 8px labels (`Cascading/style.css:52`), 8–9px badges and descriptions (`Mega-Menu/style.css:514-519`, `:528-537`), 10px (`MultiSelect/style.css:37`, `Date-Range/style.css:230`, `Profile/style.css:189`, `Navigation-Dropdown/style.css:297`).

### P16. Accessibility — the premium pattern is a regression pattern
- Measured: native inputs hidden with `display:none` (4 folders) instead of the visually-hidden technique the Hamburger toggle uses (`Hamburger/style.css:437-442` is the one correct one); controls built from `div`/`li`/`i` (Pagination, MultiSelect, Search, Time, Cascading, Sidebar, Toast close, password eye, Bulk bar); hover-only menus (Navigation-Dropdown); `visibility:hidden` labels on icon links (Dock); unlabeled icon buttons (Gallery, Profile); `outline:none` ×15; ARIA in 2/27; reduced-motion in 0/27. - Translation: already the library's baseline — react-aria primitives, `focus-ring.css`, `withOwnHitTarget`, APG keyboard maps. The lesson is only a warning for showcase pages: never copy a premium file's markup.
